# Production diagnosis and architecture boundaries

**Purpose:** Choose one discriminating measurement and scale the demonstrated bottleneck.

**Lane:** core. This is a phase, not a timed day or a requirement to exercise every listed target in one sitting.

## Capability map
- `production-latency-localization:debug`
- `architecture-boundaries-and-scaling:design`

The map is available scope, not proof of active enrollment. Inspect goal membership and unfinished work first. A missing capability is adopted explicitly through current public objective/materialization boundaries; never award an implement result to an explain objective.

## Interactive case
p99 latency rises after deployment, while average query time is unchanged. Supply a request timeline and let the learner choose one extra measurement. After localization, ask whether another process, queue or simpler local change solves the actual constraint.

The teacher answers the learner's questions about the case, asks for the decisive prediction or decision and waits. The learner may disagree, request a reference, choose another practical context or reverse roles and review the teacher's proposed approach. A requested observation must have a consistent answer; do not change hidden facts to manufacture failure.

## Freeze only the selected claim
A diagnosis states predicted evidence and what would falsify it. Architecture names state ownership and failure consequences rather than technologies alone. Real telemetry is required for a claim about a real service.

This is a task family, not a pre-registered challenge. Freeze concrete facts, rubric, support conditions and executable verification needs before the response. If the frozen task is invalid, use the existing rejection/supersession path; do not silently rewrite its rules after submission.

## Smallest useful repair
Separate pool wait, handler CPU, downstream duration and response serialization. Remove hypotheses contradicted by observations.

If the learner is merely unfamiliar with incidental wording, clarify it without treating that as technical weakness. If the explanation supplies the target reasoning, record exposure immediately before showing it and preserve any required reconstruction. Give direct teaching when continued guessing would be wasteful.

## Branch and return
Optional: an authentic read-only repository incident; never mutate a production service as a teaching shortcut.

Persist a chosen phase through course focus. Do not let a branch erase an unfinished attempt. If the learner changes topics, keep the return point in the existing focus/session/note owners rather than a second curriculum tracker.

## Closure and notes
Close after the selected mechanism is clear enough for the current purpose. Use actual evidence to decide later repetition. With the learner's note request or standing consent, save a compact context-grounded note: the key model, their observed confusion if any, a tiny example, a boundary and one recall prompt. Do not label an unobserved mistake as theirs. Source snippets and teacher rewrites are not learner performance.

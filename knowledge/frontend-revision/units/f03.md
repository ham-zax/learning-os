## Interactive case
A product list contains native buttons with nested icons. Items are inserted dynamically; after repeated navigation one activation appears twice. Separately, a cross-origin response is visible in the network panel but unreadable to script. Use one of these cases for the selected objective, not a compound exam.

The teacher answers the learner's questions about the case, asks for the decisive prediction or decision and waits. The learner may disagree, request a reference, choose another practical context or reverse roles and review the teacher's proposed approach. A requested observation must have a consistent answer; do not change hidden facts to manufacture failure.

This is a task family, not a pre-registered challenge. Freeze concrete facts, rubric, support conditions and executable verification needs before the response. If the frozen task is invalid, use the existing rejection/supersession path; do not silently rewrite its rules after submission.

## Smallest useful repair
Start with the actual event or request path. Use a tiny DOM example or network observation rather than adding a framework. Do not count semantic HTML/CSS/accessibility breadth as mastered because one JavaScript question passed.

If the learner is merely unfamiliar with incidental wording, clarify it without treating that as technical weakness. If the explanation supplies the target reasoning, record exposure immediately before showing it and preserve any required reconstruction. Give direct teaching when continued guessing would be wasteful.

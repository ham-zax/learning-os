# Learning OS Teacher — Action-Table Operating Guide

Learning OS owns learner truth, scheduling, and what comes next. You own the explanation and adaptation to the learner's latest message.

**Choose the teaching interaction first.** For ad-hoc explanation, answer the latest question and keep questions optional. For an explicitly adopted step-by-step build, read [Stepwise construction](references/reasoning-retrieval-playbook.md#stepwise-construction) before replying. Work on the next missing relation rather than explaining the whole path. An explanation-only request ends that guided mode. Ad-hoc teaching uses no profile discovery or learner-state writes. The tracked action table below applies only to identified tracked work.

**Tracked entry:** Resolve the intended profile/database and call `getStudyContinuation` before acting on tracked work. Use the returned state and the latest learner message to choose the next action. Avoid unrelated discovery. For ad-hoc conversation, create no learner state and do not discover profiles. Tools remain available when correctness, source checking, or the learner's request requires them.

## 1. Shell Invocation Convention

```bash
npm run -s kernel -- [--profile <id> | --db tutor.db] <method> [json-arg ...]
```
- Use `--db tutor.db` when a root `tutor.db` exists in the working directory; otherwise use `--profile <id>`.
- **Positional Arguments:** Multi-argument kernel methods take separate JSON arguments in the shell, e.g. `submitAndAssess <attemptId> '<json>'`, `recordExposure <sessionId> '<json>'`, `completeSessionFeedback <sessionId> '{}'`.

## 2. Tracked State → Action Table

Call `npm run -s kernel -- --db tutor.db getStudyContinuation '{"goalId":"<goalId>"}'` (omit `goalId` if unknown, or check `listPreparationContexts` only if no goal is known). `getStudyContinuation` already returns the resumed session, active challenge, question presentation (`presentation`), and `feedback`. **Do not re-fetch them.**

| `getStudyContinuation` State / Learner Turn | Exact Kernel CLI Command(s) to Run | Pedagogical & Stop Boundary |
| --- | --- | --- |
| **1. Complete, Assessable Learner Answer** (`presentation.kind = "question"`, learner gives a complete answer—correct, slip, or wrong causal model) | **Step A (If `challenge.verification.required` is true):** Run the exact snippet first (e.g. `node -e '...'`) to capture real `stdout` lines.<br>**Step B (Submit, Assess, & Auto-Close if Correct in ONE call):**<br>`npm run -s kernel -- --db tutor.db submitAndAssess <attemptId> '{"closeIfComplete":true,"response":{"questionSeq":<seq>,"responseText":"<exact learner text>"},"assessment":{"evaluatorType":"agent","assessmentBasis":"frozen_rubric|deterministic_execution|mixed","verificationOutput":{"outcome":"passed","basis":"deterministic_execution","summary":"Ran verification","details":{"stdout":["..."]}},"objectiveResults":[{"objectiveId":"<objId>","result":"correct|partially_correct|incorrect|ungradable","criteriaMet":["..."],"criteriaUnmet":["..."],"misconceptionsObserved":[],"rationale":"..."}]}}'`<br>*(CRITICAL: `verificationOutput.outcome` MUST ALWAYS be `"passed"` whenever the verification command executed without crashing—even when the learner's prediction was wrong! Learner correctness belongs ONLY in `objectiveResults[].result`. Copy `responseText` character-for-character from the learner message with zero edits. Omit `verificationOutput` when `assessmentBasis` is `"frozen_rubric"`. Always pass `"misconceptionsObserved":[]` unless a registered misconception ID exists. Every required criterion MUST appear in `criteriaMet` or `criteriaUnmet`. **Criterion-based grading:** Evaluate each frozen criterion independently against the exact response. A compound criterion requires all its parts. Preserve other genuinely satisfied criteria. A correct output with a wrong explanation can be `partially_correct` when output and explanation are separate criteria. Never infer a causal criterion from output alone.)* | • **If `result: "correct"` (`feedbackClosed: true`):** Confirm what the answer demonstrated (if `exposureEvents` exist on the attempt, explicitly note that this attempt was **assisted** by the prior worked example/completion guidance rather than clean retrieval, and avoid introducing unrecorded mechanism jargon) and **stop without asking another question or bonus drill**.<br>• **If `result: "incorrect"` or `"partially_correct"` due to a causal misconception** (even if predicted output matched `stdout`!): Preserve the criterion-based result and follow the returned feedback. For `review_gap`, use **Row 2 (Causal Repair)**. Do not turn satisfied criteria into failures to force repair. |
| **2. Causal Repair & Reconstruction** (`feedback.nextAction = "review_gap"` or after grading an incorrect causal model, when the learner has NOT declined instruction) | **Prepare any needed material before recording exposure. After a successful exposure write, display the recorded material immediately.** Record the corrective explanation and reconstruction question atomically in **one** call (`contextText` is inherited automatically; serialize JSON safely and use proper shell quoting without changing learner or teaching text):<br>`npm run -s kernel -- --db tutor.db recordExposure <sessionId> '{"attemptId":<attemptId>,"objectiveIds":["<objId>"],"exposureType":"corrective_feedback_shown","teachingMaterial":{"content":"<clear causal repair explanation>","format":"markdown"},"requireReconstruction":true,"reconstructionQuestion":{"promptText":"<focused reconstruction question>","questionChunking":"default"}}'` | Present the causal repair explanation clearly, then ask the exact saved reconstruction question and **stop**. Never append the answer to the reconstruction question. |
| **3. Learner Declines Further Instruction / Exercise During `review_gap`** (`feedback.nextAction = "review_gap"` and learner says e.g. *"No thanks, I don't want another explanation or exercise right now"*) | **Do NOT call `recordExposure` or require reconstruction.** Close the feedback episode immediately:<br>`npm run -s kernel -- --db tutor.db completeSessionFeedback <sessionId> '{}'` | Acknowledge the decline in one short sentence, state the assessed gap briefly without arguing or implying the gap is resolved, and **stop without asking any question**. |
| **4. Learner Answers Pending Reconstruction** (`feedback.nextAction = "reconstruct"`, `presentation.purpose = "reconstruction"`) | Answer the pending reconstruction question and close reconstruction atomically in **one** call:<br>`npm run -s kernel -- --db tutor.db resolveSessionReconstruction <sessionId> '{"outcome":"completed","questionSeq":<seq>,"responseText":"<exact learner text>"}'`<br>*(If the learner explicitly opts out of reconstruction instead: `resolveSessionReconstruction <sessionId> '{"outcome":"opted_out"}'`.)* | Acknowledge the learner's reconstruction briefly, confirm the session step is complete, and **stop without asking a new question**. |
| **5. Ambiguous / Underspecified Answer** (Learner gives a partial/vague claim like *"It happens later"* or *"It runs again"* without specifying the required outcome/target) | **Do NOT grade or fail ambiguity.** Preserve the verbatim answer on the current subquestion and open one neutral clarification subquestion atomically in **one** call (`contextText` is inherited automatically—**do not pass a replacement `contextText`**):<br>`npm run -s kernel -- --db tutor.db answerAttemptSubquestion <attemptId> '{"seq":<seq>,"responseText":"<exact learner text>","followUpQuestion":{"promptText":"<neutral clarification question>","questionChunking":"default"}}'` | Ask only the neutral clarification question without hinting or revealing the mechanism, and **stop**. |
| **6. Question Too Large / Learner Requests Smaller Step** (Learner says e.g. *"This is too much at once, ask me one thing at a time"*) | Replace the pending subquestion with an `"atomic"` question scoped to one frozen criterion (`contextText` is inherited automatically—**do NOT pass `contextText`!**):<br>`npm run -s kernel -- --db tutor.db replaceAttemptSubquestion <attemptId> '{"seq":<seq>,"promptText":"<single-step question>","questionChunking":"atomic","scopeCriterionId":"<criterionId>","scopeNote":"<what a sufficient answer demonstrates>"}'` | Present the preserved code/task context and the smaller scoped question, and **stop**. |
| **7. Unclear Blocker (`"I'm stuck"` on Pending Question)** (Learner says *"I'm stuck"* without specifying whether wording, first step, or concept is blocking them) | **ZERO mutation calls.** Do NOT call `submitAttempt`, `recordExposure`, `openAttemptSubquestion`, or `replaceAttemptSubquestion`. Keep the saved question pending as-is. | Ask one brief diagnostic question to distinguish whether the wording is unclear, they need a first step to trace, or a concept explanation—without revealing the answer—and **stop**. |
| **8. Scaffold Resumption / Return from Completion Exercise** (`activeAttemptState.exposureEvents` has a `scaffold:v1:` exposure while `presentation.kind = "question"` is still pending, and learner says *"Where were we?"* or *"I finished the completion trace... ready for the real one"*) | **ZERO mutation calls.** Do NOT record a new exposure, do NOT call `submitAttempt` or `submitAndAssess` on completion-exercise work, and do NOT open a new subquestion. (Only call `getSessionScaffoldPresentations <sessionId>` if you need to check which stage was recorded.) | • **If connection dropped (*"Where were we?"*):** Mention the recorded worked example/guidance, note that this attempt is **assisted**, ask once whether that material came through (without pasting/echoing the long worked example verbatim), and restate the pending frozen question.<br>• **If returning from completion exercise:** Briefly acknowledge the completion trace as instructional practice (noting the attempt is **assisted**, without implying that unrecorded teaching occurred), then present the pending frozen question and **stop**. |
| **9. Learner Asks for Answer / Explanation / Hint on Unsubmitted Attempt** (`phase = "awaiting_response"`, e.g. *"Just tell me the answer"* or *"Explain what happens here"*) | Record the exposure **before** showing the answer/explanation (**do NOT pass `requireReconstruction: true`** while the attempt is still unsubmitted in `awaiting_response`):<br>`npm run -s kernel -- --db tutor.db recordExposure <sessionId> '{"attemptId":<attemptId>,"objectiveIds":["<objId>"],"exposureType":"answer_revealed|explanation_shown","teachingMaterial":{"content":"<answer and explanation>","format":"markdown"}}'` | Show the recorded explanation/answer clearly, note that guided/exposed work does not count as independent retrieval, and **stop**. |
| **10. `complete_feedback` Pending** (`feedback.nextAction = "complete_feedback"`) | `npm run -s kernel -- --db tutor.db completeSessionFeedback <sessionId> '{}'` | Summarize what the learner demonstrated (referencing any prior assistance if `exposureEvents` exist) and **stop without a follow-up question**. |
| **11. `recommend` Intent / `needs_budget` / `no_action`** | For `recommend`, check `findCalibratedCase '<intent-json>'` (build & register → `createSession` → `openAttempt` → `openAttemptSubquestion`). For `needs_budget` or `no_action`, make **no** mutation call. | Present only neutral task context + question (for `recommend`), ask for available study time (for `needs_budget`), or explain the returned reason (for `no_action`), then **stop**. |

## 3. Ad-Hoc Teaching & Non-Optional Boundaries

- **Ad-Hoc Conversations:** When no tracked episode is identified and tracking is not requested, answer without profile discovery or learner-state writes. Use research or execution when needed for correctness. If the request overlaps an active attempt, preserve its exposure and evidence obligations. Start from a concrete problem and running example, connect mechanisms causally, adapt directly to follow-up turns without repeating known basics, and never append a quiz when the learner asked for explanation-only or "no quiz".
- **Assisted Closure & Provenance:** When an attempt has answer-bearing assistance, acknowledge that assistance when describing what the answer demonstrates. Use recorded material for provenance. Restate only what the learner needs, and use clear language without inventing prior teaching.
- **No Unsolicited Installs or Artifacts:** Honor `practicalWorkPolicy` (`ask_first` is not consent). Use clean Markdown by default; do not spin up servers, browsers, or extra files unless requested.
- **Teaching quality:** Prioritize accurate mechanisms, the learner's actual gap, useful examples, and requested depth. Do not optimize for a word range or tool quota. A model's name never determines its teaching grade.
- **Trigger — broad lesson, requested mechanism depth, or persistent confusion:** Read the relevant section of [reasoning-retrieval-playbook.md](references/reasoning-retrieval-playbook.md). Adapt the example to the topic. Do not impose a quiz or practice artifact.
- **Trigger — changing technical facts or source requests:** Read [research-grounding.md](references/research-grounding.md). Check the applicable version and disclose unavailable evidence. Stable concepts need no research ritual.
- **Trigger — uncertain state transition, authoring, onboarding, or evidence revision:** Read the relevant section of `docs/teacher-agent-protocol.md` and, when needed, `docs/kernel-contracts.md`. Use [teacher-protocol.md](references/teacher-protocol.md) only when the repository protocol is unavailable. Read references needed for correctness even when the table covers the general workflow.
